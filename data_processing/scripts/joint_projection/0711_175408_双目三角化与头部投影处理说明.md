# 0711_175408 外部双目三角化与头部投影处理说明

## 1. 数据与坐标系

- 外部双目刚体为 CH01，头部刚体为 CH07；本条数据没有腕部刚体。
- 外部相机使用 CAM_A / CAM_D，头部相机也使用 CAM_A / CAM_D。
- 外部双目优先使用 Kalibr 标定的完整旋转和平移，不能只使用理论纯基线。
- 外部三角化点先转换到 CH01，再经 Kabsch 刚体变换进入 CH07/世界坐标，最后使用头部相机刚体外参投影。
- 本次验证使用 CH07 轴修正 `Z +90°`，并保留固定平移修正；旋转和平移的方向必须通过实际投影图复核，不能仅凭矩阵命名判断。

## 2. 时间与丢帧处理（最容易出错）

- 所有相机虽然共用外部触发，但不能按“第 N 个解码包”直接对齐。
- H265 遇到坏包时，FFmpeg 会错误隐藏或生成补偿帧；可解码包数量会小于转码 MP4 帧数。
- 当转码 MP4 帧数与该相机 timestamp 行数完全相等时，MP4 帧号应直接对应 timestamp 的相机内行号。旧方法把解码包序号当 MP4 帧号，约第 1000 帧时已提前 42 个触发周期（约 0.84 秒）。
- timestamp CSV 中两路相机行可能交错。必须先按 module、camera 分组，再分别从零编号，不能使用 CSV 全局行号。
- 严格输出以 trigger sequence 求交集。任意一路缺 trigger、原始 H265 包不可解码，或外部双目姿态质量不达标时，四路一起删除该触发帧。
- 删除后所有输出统一以 50 FPS 写出，因此时间被压缩，但各视角仍逐帧同 trigger。保留 `strict_kept_trigger_sequences.json` 以恢复原始触发时间。
- 上述“删帧后仍固定 50 FPS”会导致肉眼看到加速，即使文件属性仍显示 50 FPS。例如 2824 个原始时间槽只有 1897 个被写出时，时长会从 56.48 秒缩短到 37.94 秒。
- 因此最终应同时生成两版：`event` 严格事件版真正删帧；`source_time` 原时间轴版在无效 trigger 期间保持上一张完整可信的同步画面。后者不展示坏帧、不压缩动作时间，仍是恒定 50 FPS；短暂冻结是有意设计。

## 3. 人体选择与外部双目三角化

- 外部双目使用 YOLO11x-pose，分别保留多人候选，不在单目阶段过早锁定人物。
- 在同一 trigger 内用左右候选的极线/射线一致性、身体拓扑和时序连续性配对。
- 三角化使用双目鱼眼/全向相机模型先反投影为射线，再求两条射线的最近点中点。
- 质量门限至少包括：有效身体关节数、肩/肘/髋/膝覆盖、射线间距和双目重投影误差。
- 当前严格版门限：身体关节不少于 10 个；肩、肘、髋、膝关键集合至少出现 7 个；射线间距中位数不超过 20 mm；重投影误差 P90 不超过 12 px。
- 三角化结果先做短窗口中值滤波，再进入坐标系变换和头部投影。

## 4. 肩、肘与手部替换

- 外部双目投影仍作为完整骨架主体，髋、膝、踝等关节不直接用头部单目结果替换。
- 对每个头部视角，先用当前外部投影的鼻、肩、肘、腕、髋位置，在该帧头部 YOLO 多人候选中选择距离最接近的本人。
- 肩和肘：头部检测置信度达到 0.18 后，替换对应的外部投影 2D 点。
- 手部不再依赖腕环 Tag。实测该视频中的腕环可被 `tag16h5` 解码，而不是 `tag25h9`；但 Tag 中心受腕环曲面、遮挡和鱼眼畸变影响，并不稳定等于人体腕关节。
- 最终手部方法使用 MediaPipe Hand Landmarker 的 21 点手部模型。先沿外部投影的肘—腕方向生成局部 ROI，向手掌方向少量外推并放大，再在 ROI 内识别手；骨架端点使用 landmark 0（wrist）。官方模型也提供 handedness 和 21 个手部 landmark，但左右手归属以外部投影 ROI 为准，避免鱼眼画面中的左右分类错误。
- 手模型 wrist 与原投影距离超过 320 px 时拒绝替换；检测不到时保留外部投影，不使用低置信度猜测。
- 可视化颜色：青色为外部双目投影主体，黄色为头部检测替换的肩/肘，品红色为手部模型替换的 wrist。

## 5. 抖动滤波

- 先对每个关节使用 5 帧中值滤波，抑制偶发离群点。
- 再使用随残差和置信度变化的自适应 EMA：运动小时强平滑，真实快速运动时自动提高响应速度。
- 每帧最大位移限制：躯干/头部 30 px，肘/膝 40 px，腕/踝 52 px；低置信度时门限乘 0.55。
- 不能使用过低的固定 EMA 系数，否则骨架会明显滞后；也不能只做逐帧限幅，否则持续误检会缓慢漂移。
- 滤波应在统一 trigger 序列上完成，输出视频、CSV 和 sequence 清单必须使用同一筛选结果。

## 6. 本次仅处理前 1/3

- 以头部每路 timestamp/MP4 的总帧数为基准，使用 `[0, floor(N/3))` 的源帧区间。
- 先按源时间截取前 1/3，再应用严格四路求交和质量筛选；不能简单截取严格版输出的前 1/3，因为严格版各时间段删除帧数可能不同。
- 输出中同时保留 source frame index 和 trigger sequence，方便后续与动捕或原始视频再次对齐。

## 7. 每次新数据的检查顺序

1. 核对每路 timestamp 行数、MP4 帧数、可解码 H265 包数。
2. 随机检查至少三个时段的共同 trigger 画面是否同步。
3. 查看外部双目重投影误差、射线间距和典型骨长分布。
4. 先画 CH01/CH07 与相机 z 轴，确认坐标系方向，再看人体投影。
5. 检查本人候选是否会被路人替换，尤其是肩、肘和腕部。
6. 对比滤波前后动作相位，确保抖动下降但没有明显时间滞后。
7. 最后才批量渲染组合视频，并保留 CSV、summary 和 trigger 清单。
