## 2. 外部触发约定

采集时所有相机理论上使用同一个外部触发信号。处理时不能只相信“同一序号帧自然对齐”，必须以 timestamp/trigger 表为准。

关键约定：

- `[ARMED]` 之后再开 trigger。
- `trigger_events.csv` 记录第一帧外部触发相关信息。
- `timestamps.csv` 使用 OAK device timestamp。
- 处理阶段以 trigger sequence 求交集，而不是以文件帧号求交集。

## 3. H265/MJPEG 与帧号问题

之前已经确认过一个很容易踩的坑：H265 坏包、丢包或解码补偿会造成 packet 序号和 MP4 帧号不一致。

因此：

- 不要把 H265 packet 序号直接当 MP4 帧号。
- 转码后如果 MP4 帧数与该相机 timestamp 行数完全一致，可以按相机内帧号匹配。
- 如果某路缺 trigger 或解码帧不可用，严格版要把这一 trigger 的所有相机帧一起删掉。

## 5. 采集后的最低检查

每次新采集数据后建议先检查：

1. 每路视频帧数。
2. 每路 timestamp 行数。
3. trigger_events.csv 是否存在第一触发。
4. CAM_A / CAM_D 是否确实都有画面。
5. 是否存在某一路严重丢帧。
6. 是否需要生成 source_time 版本，避免严格删帧后视觉加速。

## 6. 与本周结论相关的特殊问题

`0711_214559` 这一组数据被确认外部相机触发线丢帧严重，因此严格删帧后视频会不连续，动作信息损失较多。这个问题不应该用滤波、offset 或投影模型去“修”，因为根因在采集同步质量。
