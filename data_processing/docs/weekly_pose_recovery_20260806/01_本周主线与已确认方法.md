# 本周主线与已确认方法

更新时间：2026-08-06

## 1. 本周核心目标

本周的核心目标是：用外部双目相机得到稳定的 3D 人体骨架，再把它投影到头部双目鱼眼视角中；在外部双目深度不准的情况下，引入头部双目的少量 2D/3D GT 来约束和修正 3D 骨架。

当前工作已经从“单纯外部双目三角化”推进到“外部 3D 骨架 + 头部手动/检测 GT 加权拟合”的方向。比较可信的一版是 `head_manual_gt_fit_5s15s_final_v2`，它用手动标注的头部双目 2D 关键点反投影成 3D GT，再对外部三角化 3D 骨架做全局拟合与骨长约束。

## 2. 已确认保留的处理思想

### 2.1 时间对齐

最新数据使用新版对齐结果，采用 `offset0`，严格按 trigger 对齐。凡是任意一路相机缺 trigger 或缺有效帧，该 trigger 对应帧都要从严格同步结果中删除。

当前严格对齐基线：

- 本地：`C:\Users\hand\Desktop\0711_214559\realigned_offset0_rawsource_full6207`
- 远程：`/home/gaoweijian/0711_214559/realigned_offset0_rawsource_full6207`
- 帧数：6207
- fps：50
- 时长：约 124.14 秒

### 2.2 外部双目 2D 检测和三角化

外部双目使用 RTMPose / YOLO pose 分支做人体 2D 关键点。当前更偏向 RTMPose WholeBody/RTMPose 分支，因为之前和 YOLO pose 对比时，RTMPose 在头部/鼻子相关验证里更合适。

三角化流程：

1. 对外部 CAM_A / CAM_D 的 2D 关键点按同一 trigger 匹配。
2. 用全向/鱼眼相机模型把 2D 点反投影成射线。
3. 用双射线最近点中点恢复 3D。
4. 转到外部刚体 CH01 或世界坐标，再根据 CH07 对齐到头部刚体坐标。
5. 最后投影到头部相机 CAM_A / CAM_D。

### 2.3 滤波策略

已经确认过的关键方向是：优先在外部双目 2D 坐标阶段做抖动抑制，再进行 3D 三角化。过强的 3D 滤波会导致骨架明显跟不上动作。

当前保留两套概念：

- 强滤波：适合看静态稳定性，但动作会滞后。
- 弱滤波：当前更适合全量投影，动作跟随更自然。

弱滤波版本保留：

- median window：3
- Savitzky-Golay window：9
- torso constraint：弱约束
- 不引入时间相位偏移

### 2.4 头部相机坐标与外参

当前头部投影需要使用已经确认过的 `xy_swap + z_flip` 基，矩阵：

```text
[[0, 1, 0],
 [1, 0, 0],
 [0, 0, -1]]
```

这个结果等价于之前视觉上反复确认过的 `z+90` 方向修正，但需要以当前“xy 对调 + z 反向”的头部刚体/相机坐标描述为准。

头部相机相对刚体的理论位置曾确认：

- CAM_A：`[-89, 26.3, -53.8] mm`
- CAM_D：`[85, 26.3, -53.8] mm`

后来确认两相机位置曾经反了，当前应以修正后的 head 外参为准。原则是：实测 head 外参只作为理论外参位置的微调，不应让旋转坐标系偏离理论定义。

### 2.5 鼻子 GT 的作用

鼻子相对头部刚体 CH07 可视为固定：

```text
nose_in_CH07 = [0, -15, -125] mm
```

鼻子 GT 的正确使用方式：

- 头部刚体 CH07 给出鼻子的 3D GT。
- 视觉模型或手动标注给出鼻子的 2D GT。
- 二者用于校准外部双目三角化的深度/整体 3D 位置误差。
- 不能只是把某一帧 nose offset 直接硬套到所有骨架上。
- 更合理的是取一段时间或多帧约束，避免逐帧自适应引入抽动。

### 2.6 五点/多点头部 GT 优化

用户后来明确希望使用头部视角检测/手动标注出来的 2D 真值反投影到 3D，作为外部骨架优化的参考。

当前最新手动 GT 版本使用：

- 鼻子
- 左右肩
- 左右肘
- 左右腕
- 左右脚尖
- 其他低权重点

高权重点：鼻子、肩、肘、腕、脚尖。低权重点：其余关节。

优化目标：

- 外部 3D 骨架仍作为原始三角化 GT 或 baseline。
- 头部双目反投影得到另一套 3D GT。
- 对外部 3D 骨架做全局拟合。
- 用头部反投影得到的肩宽、大臂、小臂作为骨长目标。
- 验证时渲染 3D 可旋转页面和头部双目 2D 投影视频。

## 3. 已否决或需避免的路线

- 视觉误差扫描得到 `77 frame` 对齐：已被否决。
- 旧的 `+71 ms` offset：新对齐后不再使用。
- 用头部投影误差反推时间戳：容易误导，不能作为默认策略。
- 用错误坐标系下的 CH07 列：会把骨架带到完全错误的位置。
- 过强滤波作为默认全量视频：会导致动作跟不上。
- 用 tag 作为手部关键点主方法：tag 中心不稳定，不等同于 wrist 关节。
- 对头部 2D 坐标本身做“优化”：用户明确要求优化 3D 骨架，而不是改 2D GT。

## 4. 当前最可信的阶段性结论

1. 外部双目 2D 骨架本身比较准，主要问题在深度和坐标链。
2. 新版 timestamp 严格对齐后应采用 offset0，但数据本身触发线丢帧严重，会造成全量视频不连续。
3. 头部相机投影模型必须按 180 度鱼眼/全向模型处理，不能当普通 pinhole。
4. 头部相机坐标系和刚体坐标系的 z 方向不同，这一点之前造成过巨大方向误判。
5. 当前头部手动 GT 拟合能明显拉近关键关节，但 head 双目反投影本身有几十毫米级 ray miss，需要继续人工审核。
